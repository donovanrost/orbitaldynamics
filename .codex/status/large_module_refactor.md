# Large Module Refactor Status

Overall objective:
Reduce maintenance risk in the largest OrbitalDynamics modules and tests through
facade-preserving, responsibility-focused extraction with no public behavior,
artifact-contract, deterministic-output, or schema-export changes.

Current slice:
Cadence-import row JSON Schema provider-manifest extraction.

Status:
Published as `283db7c7`.

Selected slice:
Replace the cadence-import row JSON Schema dependency/property `case`
dispatchers in `Schema` with explicit lazy provider manifests consumed by
`CadenceImportManifestJsonSchema`.

Why this slice:
`schema.ex` remains the live production hotspot at 10,085 lines and 895
public/private clauses. Lines 4,980-5,152 contain two mechanical dispatch
tables whose names belong to the cadence-import row schema and whose values
must remain facade-private schema builders. A lazy provider manifest keeps
those builders in `Schema` while moving lookup mechanics to the row schema
owner, reducing routing noise without eager evaluation or broad callback churn.

Public facade to preserve:
`OrbitalDynamics.Schema.json_schema/1`, `json_schema_bundle/0`, all schema write
functions, exact `cadence_import_manifest.v1` generated bytes, and executable
validation behavior.

Likely files:
- `lib/orbital_dynamics/schema.ex`
- `lib/orbital_dynamics/schema/cadence_import_manifest_json_schema.ex`
- `.codex/status/large_module_refactor.md`

Likely verification:
- exact before/after cadence-import schema SHA-256
- checked-in cadence-import schema byte equality
- JSON Schema export contracts and schema export task tests
- compile, format, diff hygiene, and bounded review

Definition of done:
All dependency keys and zero-arity providers remain exact and lazy; the two
private dispatchers disappear; public schema APIs and generated bytes are
unchanged; focused/export tests pass; and bounded review finds no blocker.

Outcome:
`CadenceImportManifestJsonSchema` now owns lazy provider resolution for its row
schema. `Schema` supplies explicit manifests containing the same 42 schema
providers and 13 property providers, in the same order, as the removed private
`case` dispatchers. Every provider remains a zero-arity function capture, so
schema construction remains lazy. `schema.ex` shrank from 10,085 to 10,000
lines; the row schema owner grew from 798 to 807 lines, for a net 76-line
reduction across the production boundary.
