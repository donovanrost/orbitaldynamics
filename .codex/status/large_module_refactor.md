# Large Module Refactor Status

Overall objective:
Reduce maintenance risk in the largest OrbitalDynamics modules and tests through
facade-preserving, responsibility-focused extraction with no public behavior,
artifact-contract, deterministic-output, or schema-export changes.

Current slice:
Cadence-source-review row JSON Schema provider-manifest extraction.

Status:
Published as `799ebda9`.

Selected slice:
Replace the cadence-source-review row JSON Schema dependency/property `case`
dispatchers in `Schema` with explicit lazy provider manifests consumed by
`CadenceSourceReviewRowJsonSchema`.

Why this slice:
The cadence-import slice proved the local lazy-provider API with exact schema
bytes. The adjacent cadence-source-review row has the same ownership problem:
35 schema and 13 property key/provider pairs live in two facade-private
dispatchers, while their lookup names belong to the row schema owner. Reusing
the proven local pattern keeps builders private and evaluation lazy.

Public facade to preserve:
`OrbitalDynamics.Schema.json_schema/1`, `json_schema_bundle/0`, all schema
write functions, exact `cadence_import_manifest.v1` generated bytes, and
executable validation behavior.

Likely files:
- `lib/orbital_dynamics/schema.ex`
- `lib/orbital_dynamics/schema/cadence_source_review_row_json_schema.ex`
- `.codex/status/large_module_refactor.md`

Likely verification:
- exact before/after cadence-import schema and full-bundle SHA-256
- checked-in cadence-import schema byte equality
- JSON Schema export contracts and schema export task tests
- compile, format, diff hygiene, and bounded review

Definition of done:
All 35 schema and 13 property keys/providers remain exact and lazy; the two
private dispatchers disappear; public schema APIs and generated bytes remain
unchanged; focused/export tests pass; and bounded review finds no blocker.

Outcome:

schema. `Schema` supplies explicit manifests containing the same 35 schema
providers and 13 property providers, in the same order, as the removed private
dispatchers. All providers remain zero-arity captures. `schema.ex` shrank from
10,000 to 9,929 lines; the row schema owner grew by nine lines, for a net
62-line reduction across the production boundary.
